## Implemented interfaces

- `runEnrichment(owner, jobId, context): Promise<void>` in `runner.ts`. It claims the existing job lease; ignores already-running/terminal jobs; collects only selected sources; resumes successful collected evidence on retry; records sanitized source failures and completes ready/partial/manual/failed states. It never saves the public profile. On an interrupted process, the existing lease expires to stalled; there is no automatic retry guarantee.
- `RunContext` is **server-only**, not a request schema. The future request service must obtain the GitHub numeric account ID from the owner's identity record and its token from that same owner's encrypted cookie session, then capture them only in the `after()` closure. The provider verifies the token belongs to that numeric account. Never accept these fields from the client, persist them or log them. `openAlexApiKey` is supplied privately; page collection uses the already-confirmed stored URL/text. `fakeAi` must come from central server configuration only.
- `synthesize(owner, jobId, leaseToken, generation, evidence, identity)` in `synthesis.ts` makes one bounded Responses request for the evidence batch and returns `{ bio, bioEvidenceIds, expertise }`. The SDK request has no tools, uses `store: false`, a 20-second timeout and no SDK retry. Input includes professional excerpts and IDs, not the owner's identity, URLs, credentials or raw CV. Referenced IDs must belong to the supplied evidence; known workplace/country names, contact patterns and hiring phrases are rejected in generated text. This cannot establish factual truth or catch every paraphrase: human review is mandatory.
- The editable prompt is `PROFILE_PROMPT` in `synthesis.ts`. Its full text participates in the cache hash, alongside model, owner, selection generation and canonical evidence without retrieval timestamps. Prompt edits therefore invalidate hits. The friend's prompt review can use this file; no live call is needed.
- `professionalCv()` accepts only the bounded extracted text and returns at most five candidate professional excerpts, with no URLs. Recognized English section headings include experience, education, skills, publications, projects, research interests, certifications, grants and awards. Unknown explicit headings and sensitive/reference sections terminate the previous section. Names/front matter and unstructured text without recognized sections are not used. Multilingual/unusual CV structures can yield no excerpts; this is an honest empty result, not invented evidence.

## Cache and privacy behavior

Validated proposals are stored in existing `ai_cache` under `profile:<owner hash>:<input hash>`. The `kind` column is already plain SQL text, so adding `profile` to its TypeScript enum generates **no database migration**. Reads require the owner's live job/lease/generation and a matching unexpired CV when selected. A cache write locks/rechecks the private row, remembers its key and inserts the reply in one statement. Post-lock expiry checks use the database wall clock so lock waits cannot extend a lease. At most eight distinct cache keys are remembered per job; beyond that, the draft can complete without caching another variant.

Cancel, supersede, expiry, approval and source withdrawal erase remembered cache entries in the same guarded statement that updates private state. A late cache writer cannot insert after the lease/consent changed. Purges are owner-prefixed and limited to the profile kind, preserving B1 ask caches. No cache read/write catches or traces retain provider exception text or SQL parameters. Cache outages are misses; a fresh lease check still precedes any model request.

Source evidence is sanitized before it is stored for review or sent to AI. Contact and known sensitive lines are conservatively excluded, with ordinary phone/address formats covered by regressions. **This is heuristic filtering, not a general PII detector**: unusual headings, obfuscation and contextual sensitive claims need review. In particular, full CV parsing output remains owner-private and is not itself searchable evidence. The existing acceptance step publishes only the chosen excerpts.

The two Dash0 ask-token metric rules now select only `convo.ai.kind` refine/explain, so profile generation cannot inflate tokens/cost per ask. Profile spans still carry standard gen_ai token attributes for the Gen AI view. Reapply `dash0/signal-metrics.json` using the existing account-owned procedure in `db/Dash0.md` before enabling imports; nothing was applied to Dash0 here. The supported `is_one_of` string filter is documented in [Dash0's filter reference](https://www.dash0.com/docs/dash0/miscellaneous/tooling/dash0-cli/commands).

## Review findings and fixes

Tests were written failing first. Review found three concrete edges: abbreviated street addresses escaped filtering; unknown Markdown/reference headings could extend a professional CV section into sensitive content; and a CV could expire before its longer job/lease. Regressions now cover the address/section cases; SQL guards cover matching CV identity and job/lease/CV expiry after lock waits. The runner also rechecks a lease immediately before a model request. Requests already in flight cannot be unsent, but cancelled/expired work cannot publish or repopulate cache. Independent review found no remaining concrete blockers in this scope.
